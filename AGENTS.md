## Проверки и Git

- Перед изменениями проверить фактический root, remote, ветку, рабочее дерево, индекс и существующие файлы. Один связный набор изменений в согласованных границах; сохранять посторонние и staged-изменения владельца.
- Проверять полный diff, `git diff --check` (для staged-изменений — `git diff --cached --check`), локальные ссылки и ресурсы, смысловую согласованность затронутых переводов и целостность изменённых изображений. Не заявлять PASS для непроведённых проверок. Для статического профиля не вводить runtime или CI ради формальных проверок.
- Все tracked-файлы изменять через локальный Git или проверенный патч. Remote — `READ_ONLY_FOR_AI`: commit, push, PR, merge, tag, release и настройки GitHub выполняет владелец. Запрещены `gh`, переписывание истории и разрушительные Git-операции без отдельного разрешения.
- Не раскрывать секреты и непубличные данные, не удалять файлы и не менять права доступа вне согласованных границ. При необходимости нового решения о содержании, безопасности или инфраструктуре остановить только зависимую часть задачи.
